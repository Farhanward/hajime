# hajime-web

الطبقة التي تجعل الجهاز **يخدم**، لا التي تجعله يُقلع.

## لماذا وُجد هذا المجلد

المثبّت كان يركّب Caddy وcloudflared ولا يكتب لهما إعداداً. النتيجة جهاز يمر
بكل خطوات التثبيت بنجاح، وتقول `hajimectl status` إن الخدمتين تعملان، ولا يُفتح
موقع واحد. المكوّنان «أساسيان» في جدول الخدمات، وكانا يعملان بلا عمل.

هنا الإعداد، وقاعدته أن الموقع يُعلَن مرة واحدة.

## الملفات

| الملف | الدور |
|---|---|
| `sites.conf` | جدول المواقع. سطر لكل موقع: النطاق، والنوع، والهدف |
| `generate_caddyfile.sh` | يقرأ الجدول ويكتب `/usr/local/etc/caddy/Caddyfile` |
| `cloudflared.yml.example` | قالب النفق. لا يُكتب تلقائياً: معرّف النفق بيانات حسابك |

`Caddyfile` مولَّد ولا يُحرَّر يدوياً — التشغيل التالي يستبدله. تحرير موقع في
مكانين هو كيف ينتهي نطاق إلى مجلد العام الماضي.

## الأنواع الثلاثة

```
shop.example.com       php     /vault/www/litecart
portfolio.example.com  static  /vault/www/portfolio
orders.example.com     proxy   127.0.0.1:8090
```

`static` مجلد يُقدَّم كما هو. `php` مجلد يمر عبر php-fpm، وهو السبب الوحيد
لوجود PHP على الجهاز أصلاً. `proxy` يمرّر الطلب إلى منفذ محلي بلا تغيير.

## HTTP لا HTTPS، وهذا مقصود

كل موقع يُكتب `http://` في الإعداد المولَّد، والـ HTTPS التلقائي مُطفأ. السبب أن
Cloudflare ينهي TLS عند حافته، وcloudflared يحمل الطلب إلى هنا عبر النفق. لا
شيء يصل إلى المنفذ 80 أو 443 من الإنترنت، فلا يستطيع Caddy الإجابة على تحدي
ACME ولا الحصول على شهادة. مطالبته بالمحاولة تعطي حلقة إعادة في السجل وموقعاً
معطلاً أثناءها.

هذا القرار يتغيّر يوم يُعرَّض الجهاز مباشرة للإنترنت، ويتغيّر المولّد معه.

## المولّد يرفض ولا يخمّن

- جدول فارغ: لا يكتب شيئاً ويقول ذلك. ملف Caddy فارغ يعني بروكسي يجيب كل طلب
  بصفحة بيضاء بلا سبب.
- مجلد غير موجود: يرفض ويذكر رقم السطر. موقع يشير إلى مجلد غائب يقدّم 404
  ويبدو ساعةً كأنه عطل DNS.
- موقع `php` وphp-fpm غير مثبّت: يرفض.
- Caddy نفسه يرفض الناتج: يعيد الملف القديم مكانه. إعداد يرضى عنه هذا السكربت
  ولا يرضى عنه Caddy يترك البروكسي معطلاً بعد إعادة التشغيل التالية، وهي أسوأ
  لحظة لاكتشاف ذلك.

## النفق

```bash
cp cloudflared.yml.example /usr/local/etc/cloudflared/config.yml
```

ثم املأ معرّف النفق وملف الاعتماد. المثبّت لا يكتبهما ولا يخترعهما: معرّف مخمَّن
يعطي خدمة تعيد المحاولة إلى الأبد وكل المواقع معطلة.

قد يكون المكدّس القديم شغّل أكثر من نفق، كلٌّ في حاويته الخاصة، فربما يكون
عندك أكثر من اعتماد واحد لنقله. عرّف كل نفق بملف اعتماد منفصل، بنفس الخطوات
أعلاه.

## قاعدة واحدة في الإدخال

النفق يمرّر كل شيء إلى `127.0.0.1:80`، وCaddy يقرّر لأي موقع ينتمي الطلب من
ترويسة `Host`. قاعدة واحدة بدل قاعدة لكل موقع، لأن قائمة المواقع تعيش في
`sites.conf` وتكرارها في إعداد النفق هو كيف يفترق الاثنان.
